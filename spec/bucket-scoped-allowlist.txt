# Bucket-scoped list operations that legitimately have no flat counterpart.
# One path-pattern per line. Format must match the OpenAPI path exactly.
# Each entry should have a justification comment immediately above it.
# Read by scripts/check-bucket-flat-parity.sh.

# Webhooks are inherently per-project: a webhook subscribes to events scoped
# to a single project, so there is no meaningful account-wide aggregate.
/{accountId}/buckets/{bucketId}/webhooks.json

# Message categories are defined per project in BC3 — there is no account-wide
# categories collection. The former flat route was a modeling error that 404'd.
/{accountId}/buckets/{bucketId}/categories.json

# Client approvals and correspondences live on a project's client board, which is
# per-project by construction: Clients::{Approvals,Correspondences}Controller#index
# resolves @bucket.project.client_board_recording. bc3 draws no flat index (only a
# flat show, config/routes.rb:193-194), and its own test asserts RecordNotFound for
# a bucket with no client board. The flat spellings the SDK used to declare were
# live 404s (#588).
/{accountId}/buckets/{bucketId}/client/approvals.json
/{accountId}/buckets/{bucketId}/client/correspondences.json
